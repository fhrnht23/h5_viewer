# Задание для Codex: кроссплатформенный HDF5 Viewer/Editor

## Роль и рабочая область

Ты ведущий Python-разработчик и архитектор desktop-приложений. Работай только в каталоге:

`/Users/earyzhikov/Documents/h5-viewer`

Каталог на момент постановки задачи пуст. Создай в нём полноценный проект кроссплатформенного настольного приложения для просмотра и редактирования файлов HDF5 (`.h5`, `.hdf5`, `.he5`). Рабочее название приложения — **H5 Viewer**.

Не ограничивайся макетом, демонстрацией интерфейса или набором заглушек. Нужна запускаемая, протестированная реализация. Сначала составь исполнимый план, затем последовательно реализуй его. Не останавливайся после планирования, если нет реального блокирующего обстоятельства.

## Главная цель

Создать современный HDF5 viewer/editor на Python, который:

- открывает один или несколько HDF5-файлов;
- показывает всю доступную логическую структуру, объекты, ссылки, данные, атрибуты и свойства хранения;
- работает в двухпанельном режиме, похожем на Total Commander;
- позволяет открыть один файл в обеих панелях на разных путях либо разные файлы слева и справа;
- позволяет безопасно редактировать файлы и корректно сохранять изменения;
- не загружает большие datasets целиком в память;
- имеет расширяемую архитектуру для добавления новых просмотрщиков, редакторов, операций и доменных форматов;
- собирается и работает на Windows, macOS и Linux.

## Обязательный технологический стек

- актуальная стабильная версия Python, совместимая со всеми выбранными зависимостями;
- **PySide6 и Qt 6 Widgets** для интерфейса;
- `h5py` как основной HDF5 backend;
- низкоуровневые модули `h5py.h5*` там, где high-level API не показывает необходимые сведения;
- `numpy` для представления данных;
- `pytest` и `pytest-qt` для тестирования;
- `ruff` для форматирования и статических проверок;
- `mypy` для проверки типов;
- `pyqtgraph` допускается как необязательная зависимость для графиков.

Оформи зависимости и метаданные проекта в `pyproject.toml`. Проект должен устанавливаться стандартными Python-инструментами; не делай его зависимым только от одного менеджера окружений.

Не используй PyQt5, Electron или веб-интерфейс. Бизнес-логика и слой HDF5 не должны зависеть от PySide6.

Все комментарии и docstrings в исходном коде, а также сообщения Git-коммитов пиши на русском языке.
Идентификаторы и публичный Python API оставляй на английском языке.

## Требования к HDF5-модели

Не моделируй HDF5 как обычное дерево каталогов. Учитывай, что это граф объектов и ссылок.

Поддержи отображение:

- корневой группы и обычных groups;
- datasets;
- committed/named datatypes;
- hard, soft и external links;
- broken soft/external links;
- нескольких hard links на один объект;
- циклов, включая ссылку группы на саму себя;
- object references и region references;
- attributes для групп, datasets и именованных типов;
- scalar, simple и null dataspaces;
- shape, rank, maxshape и размер dataset;
- atomic, compound, enum, array, variable-length, string, opaque, bitfield и reference datatypes в пределах возможностей HDF5/h5py;
- byte order и строковой encoding там, где они определены;
- contiguous, chunked, compact, virtual и external storage;
- chunk shape, fill value, allocation/storage size;
- compression и filter pipeline, включая ID неизвестных фильтров;
- shuffle, Fletcher32 и scale-offset;
- virtual dataset mappings;
- dimension scales;
- пользовательский блок и доступные свойства файла;
- версию HDF5/h5py и границы совместимости формата.

Путь ссылки не является идентичностью объекта. Введи отдельные доменные типы для ссылки, объекта и открытого документа. Обход обязан обнаруживать циклы и не зависать.

Если редкий datatype нельзя безопасно редактировать через h5py, всё равно покажи его метаданные и доступное значение, но переведи конкретный редактор в read-only и явно объясни ограничение. Никогда не выполняй молчаливое приведение типа или потерю данных.

## Просмотр и редактирование datasets

Реализуй отдельную модель данных на основе `QAbstractTableModel`, а не `QTableWidget`.

Требования:

- scalar, 1D, 2D и N-dimensional datasets;
- для N-D выбор двух отображаемых осей и индексов остальных измерений;
- загрузка только видимого окна/страницы;
- ограниченный LRU-кэш блоков;
- оценка памяти перед чтением или экспортом;
- отображение чисел, bool, строк, enum и compound records;
- отдельные колонки для полей compound datatype;
- корректное экранирование и отображение bytes/Unicode;
- отображение NaN, Inf и fill values;
- редактирование ячейки или выделенного прямоугольного среза с валидацией типа и диапазона;
- операции resize только при допустимом `maxshape`;
- запрет опасной записи длинных строк в fixed-length dtype без явного подтверждения;
- отмена и повтор изменений;
- экспорт выбранного среза как минимум в CSV и NPY;
- просмотр подходящих массивов как изображения;
- необязательный график для 1D/2D числовых данных.

Ни при каких обстоятельствах не вызывай `dataset[:]` автоматически для неизвестного или большого dataset.

## Безопасное редактирование и сохранение

Прямая модификация оригинального файла не должна быть режимом по умолчанию.

Реализуй транзакционную схему:

1. Файл изначально открывается read-only либо в safe edit session.
2. Перед первым изменением создаётся рабочая копия в том же каталоге. Используй copy-on-write/reflink, если он безопасно доступен, иначе потоковое копирование с проверкой свободного места.
3. Все команды применяются к рабочей копии.
4. `Discard` закрывает handles и удаляет только рабочую копию.
5. `Save` закрывает все HDF5 handles, повторно открывает рабочий файл в отдельном процессе и валидирует его.
6. Выполняется обход структуры и проверочное чтение изменённых областей.
7. Данные сбрасываются на диск.
8. Оригинал при включённой настройке сохраняется как backup.
9. Рабочий файл атомарно заменяет оригинал операцией файловой системы после закрытия всех handles.
10. При любой ошибке оригинал остаётся неизменным, а пользователю показываются причина и путь к восстанавливаемой рабочей копии.

Добавь:

- обнаружение изменения исходного файла другим процессом;
- advisory locking там, где он доступен;
- проверку свободного места;
- crash-recovery manifest для найденных незавершённых сессий;
- настраиваемые резервные копии;
- подробный журнал ошибок без включения пользовательских данных по умолчанию;
- предупреждение перед повышением версии формата HDF5;
- сохранение исходных version bounds, если новые возможности этого не требуют.

Изменение immutable-свойств dataset — dtype, storage layout, filters, fill value — выполняй через новый временный dataset и потоковое копирование данных. Не держи оба dataset целиком в памяти.

External raw storage, external links и VDS могут затрагивать другие файлы. Не заявляй атомарность таких изменений. До реализации безопасной многофайловой транзакции такие операции должны требовать явного подтверждения либо быть read-only.

Перемещение между разными файлами не является одной атомарной операцией: сначала скопируй и проверь destination, а удаление source оформи как отдельное подтверждаемое изменение.

## Undo/redo

Все пользовательские изменения должны проходить через команды приложения:

- `CreateGroupCommand`;
- `CreateDatasetCommand`;
- `CreateLinkCommand`;
- `RenameOrMoveLinkCommand`;
- `DeleteLinkCommand`;
- `SetAttributeCommand`;
- `DeleteAttributeCommand`;
- `WriteSelectionCommand`;
- `ResizeDatasetCommand`;
- `CopyObjectCommand`.

Используй `QUndoStack` только как UI-интеграцию; команды и их данные должны находиться в application/domain слоях. Для крупных data edits храни обратные блоки на диске, а не в RAM. Полный `Discard` должен быть доступен даже после очистки истории undo.

- отсутствие открытых `h5py` handles в GUI-моделях и виджетах;

`h5py` сериализует вызовы через глобальную блокировку. Не рассчитывай на параллельный HDF5 I/O в потоках. Qt threads можно использовать, чтобы не блокировать event loop, а независимые процессы — для реального параллелизма, валидации и изоляции. Не передавай открытые HDF5 handles между потоками или процессами.

## Производительность и отзывчивость

- Ленивая загрузка дерева через `QAbstractItemModel.canFetchMore()/fetchMore()`.
- Постраничный список членов очень больших групп.
- Отмена длительных операций.
- Throttled progress updates, чтобы сигналы не перегружали event loop.
- Ограничиваемый кэш.
- Никаких длительных HDF5-операций в GUI thread.
- Поиск по metadata не должен читать dataset payload.
- Сравнение и копирование выполняются блоками.
- Корректное освобождение памяти и закрытие файлов после закрытия вкладки.

## Критерии приёмки

Работа считается завершённой, когда одновременно выполнено следующее:

- приложение устанавливается и запускается документированной командой;
- можно создать и открыть HDF5-файл;
- все достижимые объекты и все типы ссылок отображаются без зависания на циклах;
- metadata и attributes отображаются для выбранного объекта;
- большие datasets просматриваются срезами без полной загрузки;
- один файл можно открыть в обеих панелях на разных путях;
- два разных файла можно открыть слева и справа;
- copy/move между панелями работает в рамках заявленной support matrix;
- можно изменить обычное числовое/строковое значение, attribute и структуру файла;
- undo/redo работает для поддерживаемых изменений;
- Save, Save As и Discard работают;
- искусственно вызванный сбой сохранения не повреждает оригинал;
- сохранённый файл закрывается и успешно повторно открывается;
- broken links, отсутствующие filters и неподдерживаемые типы дают понятную локальную ошибку, не падение приложения;
- длительные операции не замораживают GUI и допускают отмену там, где это безопасно;
