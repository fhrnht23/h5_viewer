# Безопасное сохранение

## Текущий протокол

Исходный файл никогда не открывается для записи в стандартном режиме.

1. При включении редактирования проверяется свободное место.
2. В каталоге оригинала создаются скрытая рабочая копия и recovery manifest.
3. Все команды применяются только к рабочей копии.
4. `Discard` удаляет рабочую копию и manifest.
5. Перед `Save` отпечаток оригинала сравнивается с сохранённым размером, временем изменения и
   inode. Внешнее изменение блокирует commit.
6. Отдельный Python-процесс повторно открывает рабочую копию, обходит её граф без зацикливания и
   проверяет metadata datasets через HDF5 API. Timeout или падение процесса блокирует commit.
7. Выполняется `fsync` рабочей копии.
8. Рядом создаётся timestamped backup оригинала.
9. `os.replace` атомарно заменяет оригинал рабочей копией в пределах той же файловой системы.
10. Каталог синхронизируется, recovery manifest удаляется.

При ошибке до `os.replace` оригинал остаётся неизменным. Путь рабочей копии хранится в recovery
manifest и может использоваться для ручного восстановления.

## Ограничения

- При отсутствии filesystem cloning требуется свободное место примерно с размер исходного файла.
- External raw storage, external links и VDS могут затрагивать другие физические файлы. Текущая
  гарантия атомарности относится только к самому локальному HDF5-файлу.
- Перемещение между разными файлами не может быть одной атомарной операцией.
