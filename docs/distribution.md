# Сборка и распространение

## Python-пакет

Wheel и исходный архив создаются стандартным PEP 517-инструментом:

```bash
python -m pip install -e '.[packaging]'
python -m build
```

Результаты появляются в `dist/`. Для запуска wheel нужен совместимый Python 3.10+.

## Самостоятельное desktop-приложение

PyInstaller не является кросс-компилятором, поэтому Windows, macOS и Linux пакуются на
соответствующей операционной системе:

```bash
python -m pip install -e '.[packaging]'
python scripts/build_desktop.py
```

Скрипт создаёт onedir-пакет `dist/H5Viewer` на Windows/Linux или готовый архив
`dist/H5Viewer-macOS.zip` с `.app` на macOS.
Python, PySide6, h5py, NumPy и `pyqtgraph` входят в пакет; отдельная установка интерпретатора не
нужна. macOS bundle получает локальную ad-hoc подпись, но CI-артефакты пока не подписаны сертификатом
разработчика и не notarized. Поэтому операционная система может показать стандартное предупреждение
для неизвестного издателя.

Собственные русские и английские строки встроены в приложение. Неиспользуемые системные `*.qm`
переводы Qt исключаются отдельным PyInstaller hook, что уменьшает пакет и делает сборку независимой
от состояния этих файлов в Python-окружении. macOS bundle собирается во временном локальном каталоге
и только затем архивируется: так облачные провайдеры не успевают добавить запрещённые `FinderInfo`
extended attributes внутрь подписи.

## CI

Workflow `.github/workflows/ci.yml` выполняет lint, format check, strict mypy и pytest на Python
3.10/3.12 в Windows, macOS и Linux. Отдельные jobs собирают wheel/sdist и три нативных desktop-
артефакта. Это одновременно проверяет платформенные импорты и исключает случайную публикацию
пакета, собранного для другой ОС.

## GitHub Releases

Workflow `.github/workflows/release.yml` запускается только для тегов `v*` и публикует постоянные
файлы загрузки на странице Releases:

- Windows x86-64 Setup, собранный Inno Setup;
- Linux x86-64 AppImage;
- отдельные ZIP-архивы macOS для Apple Silicon и Intel;
- Python wheel и sdist;
- `SHA256SUMS.txt` для проверки целостности всех файлов.

Перед сборкой тег сравнивается с `h5viewer.__version__` и метаданными wheel. Несовпадение прерывает
выпуск до создания Release. Для новой версии сначала измените `version` в `pyproject.toml` и
`__version__` в `src/h5viewer/__init__.py`, выполните обычные проверки, затем создайте тег:

```bash
git tag -a v0.2.0 -m "Версия 0.2.0"
git push origin v0.2.0
```

Имена установщиков и версия внутри macOS bundle формируются из проверенной версии проекта. Linux
AppImage дополнительно запускается в CI в служебном режиме проверки HDF5, поэтому в Release не
попадает контейнер, который не может стартовать.

Release-сборки пока не подписываются сертификатами Microsoft Authenticode и Apple Developer ID.
Windows SmartScreen и macOS Gatekeeper могут предупреждать о неизвестном издателе; для устранения
этих предупреждений потребуются сертификаты и секреты репозитория, а для macOS также notarization.

Entry-point плагины из внешнего Python-окружения автоматически доступны при запуске wheel. В
самостоятельный PyInstaller-пакет входят только модули, явно включённые во время сборки; механизм
пользовательской установки внешних плагинов в frozen-приложение пока не предоставляется.

Изолированная проверка перед сохранением поддерживает оба режима запуска. Python-версия вызывает
worker через `python -m`, а frozen-приложение повторно запускает собственный executable со служебным
флагом `--validate-worker`; пользовательский GUI во втором процессе не создаётся. JSON передаётся
через ограниченный временный файл, поэтому проверка работает и у Windows windowed executable без
консольных stdout/stderr.
